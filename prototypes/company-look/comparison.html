Does a dozen tokens and a brief make a tool look like its company?

Four looks were captured and six fresh agents each built a small tool. Every look-built tool was then restarted under every other look with no code change. This page shows all of it side by side.

What to judge. For each of the four rows below, does the tool on the right read as the company on the left?

The agents were never told about the look. Each got the same prompt for a tier 1 spend-request tracker, in a repo where generation had laid down look.css, the logo and a patchy-look skill holding the brief. The look capture used fallback font stacks and a placeholder logo, because brand fonts and logos can't go into the public repo. Screenshots were taken on Linux, the worst case for fallback fonts.

The four looks and the tools built in them

Left: the specimen, a fixed page Patchy owns that only the look styles. Right: the tool a fresh agent built, after pressing Load sample data.

Linear · minimal SaaS

Near-black and grey with one rationed indigo, Inter at medium weights with tight tracking, dense left-aligned lists divided by hairlines rather than boxes.

Duolingo · bold consumer brand

A white page, warm grey text and one loud green; everything you can press is chunky, rounded and uppercase, sitting on a hard 4px lip.

Vanguard · conservative finance

Calm and plain-spoken: white with near-black text and heavy headlines, black pill buttons over square fields and hairline tables, red saved for the logo and the one action that moves money.

Patchy · the default for a company with no look

Converted from the existing plan-doc style: warm cream paper on a faint grid, near-black ink, 2px borders, hard offset shadows, pill badges, system fonts.

A new look revision, no code change

Each row is one tool; each column is the look it was restarted under, the way a new revision arrives at dev start. The outlined cell is the look it was built in. Colours, fonts, radius, logo and light or dark follow in all 12 swaps. Structure and voice don't: Patchy's hard shadows survive in Duolingo's colours, and Vanguard's eyebrow and red rule stay put. Two things broke: hard-coded status colours (light pills stay light on Linear's dark ground), and density, because Linear's spacing unit is 4px where the others use 8px, so its tool grows about 50% taller under any other look.

Fonts

Top: Linear's look on its fallback stack (Liberation Sans on Linux). Bottom: the same tool with three Inter weights embedded in look.css as data: fonts. All three weights loaded inside the tier 1 frame with no platform change.

The fallback still reads as Linear, but the real font is visibly tighter. Embedding is worth it whenever the company may self-host its font. Three full weights made look.css 418 KB; Latin subsets are about a quarter of that.

Proposed verdict

Also found

  • The dev environment's agent isn't fresh. pnpm dev up puts the agent workspace under $HOME, so Claude Code loads ~/.claude/CLAUDE.md as an ancestor file even with --setting-sources project. These runs used a workspace under /tmp.
  • Agents read the global skill from node_modules. With no look, the agent found patchy/skills/patchy/references/patchy-plan-style.md in the installed package and followed it. Retiring style.md (#569) should account for that path.
  • A plain button as the primary button works, but every other button needs a recipe class, and one agent had to reset the primary style on its filter buttons.
