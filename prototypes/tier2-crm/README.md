Throwaway build for [#315](https://github.com/allisonmahmood/patchy-cloud/issues/315) on the tier 2 map (#294), on top of #314's branch (`prototype/tier2-init`, PR #380). The design is #303's resolution; nothing here re-decides it. The CRM itself is not built here: the fresh agents build it. Never merged. ## API shapes (as served in the skills)

- **Server, own stores** (`ctx.files.<store>`): `list({ prefix?, limit? (1–1000, default 100), cursor? }) → { files: FileEntry[], cursor: string | null }` names ascending; `stat(name) → FileEntry | null` (missing is null). In actions: `get(name) → { entry, bytes } | null`; `put(name, Upload | Uint8Array, { contentType? }) → FileEntry` (bytes need a content type; an Upload's claimed type is used unless overridden); `delete(name) → boolean`. Mutations reach no files. `FileEntry = { name, size, contentType, updatedAt, handle }`.
- **Server, shared stores** (`ctx.shared.<alias>`): `list`, `stat` in queries and actions, `get` in actions; no writes.
- **Upload in an action**: an argument typed `t.upload()` arrives as `{ token, size, contentType }` where the host substituted `size` (measured, authoritative) and `contentType` (the page's claim). A second use, another viewer's or another document's Upload: `not_found`.
- **Page** (tier 2, server-only): `patchy.files.url(handle)` (frame-local blob URL), `patchy.files.download(handle, filename?)`, `patchy.files.stage(bytes, { contentType }) → Upload`; `useFileUrl(handle) → { url, error }`; `useQuery(query, args) → { data, error, status }`.
- **Handle**: `fh_` + base64url(24-byte object id suffix ‖ 16-byte HMAC-SHA256 over viewer, company, consuming patch, version, object) = 57 characters. Redemption: MAC mismatch (another viewer, patch or version) → `access_denied`; the name no longer points at the object → `not_found`; store not defined by the version or share not live → `access_denied`.

## What stalled or is a stated gap

- **Sweep of unadopted staged objects**: not built. The orphan sweep only reclaims the older four-segment keys, so new-layout objects are never swept (safe, leaks). Adoption racing a sweep is therefore moot here.
- **Tier 1 consumption of shared stores**: not built; generation refuses a `sharedStore` declaration outside tier 2 (`SharedStoreNeedsTier2`).
- **Store dependants' wire shape**: a store declaration appears in `reads`, `dependants` and `has_dependants` with the store name in the `table` field; no separate `store` field.
- **Portal lifecycle actions** (admin retire/delete from the portal pages) do not wake `source:` keys; the CLI/API paths do.
- **Refresh's managed client pins** are written outside the project transaction; a failed install after a pin change is not rolled back.
- **The broker's hidden-document grace** comes from the served page; `patchy dev` uses the 30 s default.
- **`resolveUpload` runs before the per-company slot**, so an action with an Upload spends one extra company connection borrow.
- Inherited reds, not re-run to rediscover: the SDK export-list assertion (`SdkApi.test.ts`) and the migration-ledger assertion (`migrations.test.ts`).

## Design notes for the map

- **A tier 2 page had direct table access.** Before this round the runtime admitted `tables.*` from a tier 2 version, so any viewer-filtering handler could be bypassed from the page. The runtime now refuses everything but `me`, `server.call` and the two file exceptions on tier 2; this is what makes step 5's filter real.
- **Handle binding without storage.** The object id plus a MAC over (viewer, company, patch, version, object) is enough: the object id determines the source store while it is current, and "the name's pointer still equals the object" is exactly "a `patchy.files` row with this `object_id` exists". No handle table, no write in a read-only query.
- **A shared read refused inside a handler is not the viewer losing the document.** Before, it escalated to the shell's `access_denied` notice and replaced the whole page. Contained refusals (`refusedIn: "handler"`, and every file op) are the page's to present; the subscription stays, keyed on `source:<patchId>`, so reshare recovers it with no redeclaration.
- **Hook identity.** `patchy.server.m.q` returned a new function per property access, so `useQuery`'s effect re-subscribed on every render and replayed the last good value over an error. Handler functions are now cached per name, and the registry remembers the last error for late joiners.
- **Content-addressed release URLs** changed the pin on every rebuild; the refusal said "0.0.1 does not match 0.0.1". It now names the build digest.

## Decisions made where the tickets were silent

- **Redemption order**: the MAC is checked first, so another viewer or patch never learns whether a file was replaced; then the pointer (`not_found`), then reach (`access_denied`). A malformed handle is `access_denied`.
- **Mutations reach no files.** Queries list and stat; actions also get, put and delete. `stat`/`get` of a missing name is `null`; `put` returns the new entry with its handle; `delete` returns whether a file was there.
- **Upload values** are `{ token, size, contentType }`; the host replaces size and type from its record before invocation; `put(name, upload, { contentType })` may override the claimed type. Unknown, used or foreign Uploads are `not_found`.
- **Staging** is a read-kind runtime operation (unlogged, no mutation deadline) that still needs the exact Origin (it is a PUT), and only on a tier 2 version that defines a store.
- **The tier 2 page is server-only**: direct primitive calls are `invalid_request`, not `access_denied` (which would replace the page).
- **Every publish and lifecycle change of a source wakes `source:<patchId>`**, not only sharing changes; unchanged results are suppressed, so the cost is a re-run.
- **The broker cache** is 16 MiB per document and always revalidates (`If-None-Match` with the object id, 304 when still authorised).
- **Hidden documents**: the grace comes from the server (`PATCHY_PROTOTYPE_HIDDEN_GRACE_MS`, rendered into the shell); suspension aborts the stream (a snapshot in flight is dropped) and keeps the desired set; resume reopens with `resume: true`, so each query re-runs and the page keeps its last values as `resyncing`.
- **`useQuery`** was added to `patchy/preact` beside `useFileUrl`: the contract names it and every CRM screen needs it; it is not in the brief's list.
- **Variants** are chosen by `PATCHY_PROTOTYPE_VARIANT` at `init`, recorded as `prototypeVariant` in `patchy.json`, and read from there by refresh (pins), the import check and generation; absent means A.
- **Shared-store samples** are `sample.pdf` and `sample.svg` (both text, so they travel as generated files), laid down only when `fixtures/shared-<alias>/` is missing.
- **The dev instance runs with offline Clerk keys** (`pnpm prototype:crm setup`) so the fixture script and the browser command can sign owner and colleague sessions; no real Clerk users are needed.
- **The contracts source is tier 2**, replaced through its own `documents.replace` action and unshared through `patchy publish --force` with `shared: false`.
- **Fixture data**: amounts in integer US cents; emails compared trimmed and lower-cased; a missing company is an error, an unknown company is created; duplicates are skipped, not errors.
- **The Neon reader's password** lives in `.local/prototype-crm/finance.env` (mode 600), never in the tree; re-runs keep it so the registered connection keeps working.
