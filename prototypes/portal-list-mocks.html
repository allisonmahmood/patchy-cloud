Does the title earn a place in the list?

Every patch carries a name (its address), a title lifted from the page's <title> on every publish, and the description the owner writes. The three variants above make three different calls.

A drops it

Name and description only. The name is what people type and send; the description is what they read. The title is whatever the last publish's HTML said, so it can drift from what the owner means. Never shown in the list.

B drops it

Same call, harder: a column for title would be the widest, least reliable column in the table. Name links, description explains.

C shows it on the card only

The index carries name and the first clause of the description. The card leads with the title as the heading, because that is what the browser tab will say when the patch opens. Below it the address, then the description.

The scan test

Look at the 17-row inventory in A and B. Prose alone scans when every description opens with what the tool does. Rows with "No description" are the ones that need an icon or category, which argues for pushing descriptions, not for adding a taxonomy.
